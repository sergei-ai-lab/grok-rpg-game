# DragonVerse · инкубатор

Готовый сервер для `@DragonVerseBot`: личное яйцо, уникальный дракон, красивая карточка, рост, приглашения друзей и кнопка FLOCK. Владелец пользуется Telegram с iPhone; код и деплой выполняет Claude. Этот PR **не мёржить автоматически**.

## Что увидит игрок

- `/start` показывает картинку треснувшего яйца, затем карточку дракона с личным оттенком, именем, уникальным номером, редкостью и легендой из двух предложений.
- «Покормить» / `/feed`: первое кормление доступно сразу, следующее через 24 часа. Третье успешное кормление даёт взрослую стадию, седьмое — титана; бот присылает новое изображение карточки и сообщение об эволюции.
- «Показать друзьям»: выбирает чат и отправляет **изображение карточки** с личным приглашением. За нового игрока по ссылке пригласивший получает +1 бонусную еду.
- «Играть» / `/play` открывает FLOCK как Mini App. В Telegram видны имя игрока, полный экран на поддерживаемых клиентах и вибрация. Обычный браузер сохраняет прежний игровой процесс.
- `/dragon` возвращает карточку; `/quiet` выключает напоминания; `/remind` включает. Напоминание максимум раз в 24 часа, пока дракон растёт.
- `/stats` работает исключительно в личном чате владельца, чей ID указан в переменной окружения.

## Принятые решения

1. Node **22.13+ в ветке 22**, grammY для long polling, встроенный `node:sqlite`, sharp для изображений. Нет внешней базы, AI API, очереди, платного вещания или дополнительных сервисов. Railway предоставляет уже выбранный владельцем контейнер и постоянный диск; тарифные изменения этот код не делает.
2. Токен берётся только из `BOT_TOKEN`. В репозитории, карточках, SQLite и логах токена нет. `initDataUnsafe` в FLOCK используется только для отображения имени; сервер не доверяет ему для наград, идентификации или статистики.
3. Telegram ID — ключ игрока. Seed SHA-256 `dragonverse:incubator:v1:<id>` задаёт вид, имя, оттенок и редкость. Личный номер — ID в base36 без коллизий. Уникален экземпляр дракона; рисунки видов переиспользуются с персональным оттенком. Список видов сортируется перед выбором. Снимок идентичности хранится в SQLite: добавление каталога не заменяет уже вылупившегося дракона.
4. Редкость **личного экземпляра** имеет шансы common 60%, rare 25%, epic 12%, legendary 3%. Она независима от редкости вида в арт-каталоге: наличие готовых легендарных рисунков не меняет вероятности. 20 000 последовательных Telegram ID проверяются тестом с допуском 1 процентный пункт.
5. Интервал кормления — **24 часа от последнего кормления**, без зависимости от часового пояса и смены даты. Пропущенные дни не дают пакетных кормлений. После 7 кормлений рост завершён.
6. Кормление бесплатно и не требует запаса еды. За друга +1 бонусная еда в запас; на следующем разрешённом кормлении одна бонусная порция расходуется и даёт +1 **сияние**: число на карточке и более насыщенный оттенок (визуальный эффект ограничен). Бонус не обходит 24 часа и не меняет пороги 3/7. Это выбранный вариант до отдельного решения владельца об ускорении роста.
7. Источник фиксируется при первой регистрации: `tiktok`, `insta`, `ref`, `direct`. Новый действительный реферал засчитывается только один раз, только существующему пригласившему, без самоприглашений. Повторный `/start` не меняет источник и не начисляет бонус.
8. Напоминания включены при старте, игрок сразу видит `/quiet`. Они прекращаются после титана, блокировки бота или отключения. Время попытки сохраняется **до** отправки: при неоднозначном сетевом сбое одно напоминание может быть пропущено, зато повторное в пределах 24 часов невозможно. Проверка раз в минуту; отправки последовательны с ограничением скорости.
9. Мутации защищены транзакциями SQLite, уникальным invitee ID и сохранёнными результатами по Telegram update ID. Повторная доставка, другой реферер или перезапуск не удваивают еду, кормление и эволюцию. Telegram-файлы карточек кешируются по содержимому, стадии и прогрессу; после нового арта кеш обновляется.
10. Покупок нет. `src/stars.mjs` содержит только выключенные точки расширения «ускорение эволюции» и «второе яйцо», без цен, invoice или платёжных обработчиков.
11. Бот не переносит дракона/прогресс инкубатора в локальное сохранение FLOCK. Кнопка запускает существующую игру; имя человека показано отдельно от имени игрового дракона. Синхронизация аккаунтов потребует отдельного серверного контракта, её нет в этом scope.

## Арт другого агента — только чтение

Используется `public/flock/catalog.json`, формат PR `work/gpt/art-pipeline`:

```json
{
  "dragons": [{
    "id": "kaelith", "name": "Kaelith", "family": "fire",
    "legend": "Первое предложение. Второе предложение.",
    "stages": {
      "hatchling": { "art": { "status": "ready", "path": "img/kaelith-1.webp" } },
      "adult": { "art": { "status": "ready", "path": "img/kaelith-2.webp" } },
      "titan": { "art": { "status": "ready", "path": "img/kaelith-3.webp" } }
    }
  }]
}
```

Если каталога ещё нет, сканируются `public/flock/img/*-1.webp`. На исходном main `e158ad6` это Kaelith, Verdraxis, Aurelune, Ashmaw, Pyrestone и Scorchlane. Для них есть локальные семейства/легенды. Готовыми считаются только существующие локальные файлы; URL, пути вне FLOCK и симлинки наружу не читаются. Повторяющиеся SHA-256 стадий распознаются как старые заглушки.

У Ashmaw, Pyrestone и Scorchlane в исходном main стадии 2/3 копируют стадию 1. При эволюции бот меняет рамку/стадию/прогресс карточки и явно пишет «Иллюстрация новой стадии готовится». После появления настоящего арта использует новый рисунок того же вида. Чужие виды вместо недостающей стадии не подставляются. Ни каталог, ни картинки, ни `flock-v2`/`dragon-card` этот PR не меняет.

Новый файл каталога читается автоматически при следующем запросе к боту; изменение файла также сбрасывает кеш. В Docker арт упакован в образ, поэтому после мёржа арт-PR нужен **redeploy сервера**, чтобы контейнер получил свежие файлы. Некорректный/пустой каталог приводит к явной ошибке, а не к скрытой замене драконов.

## Переменные окружения

| Переменная | Обязательна | Значение |
|---|---|---|
| `BOT_TOKEN` | Да | Токен `@DragonVerseBot` из BotFather, только в секретах Railway |
| `OWNER_TELEGRAM_ID` | Да | Числовой Telegram ID владельца; единственный доступ к `/stats` |
| `DATA_DIR` | Да | `/data`; сюда монтируется **постоянный Railway Volume** |
| `GAME_URL` | Нет | По умолчанию `https://sergei-ai-lab.github.io/grok-rpg-game/flock/` |
| `FLOCK_DIR` | Нет | По умолчанию каталог `public/flock` этого репозитория; в Docker `/app/public/flock` |
| `PORT` | Нет | Railway задаёт автоматически; локальный default `3000` |

`.env.example` — образец, приложение само `.env` не загружает. На Railway переменные задаются настройками сервиса.

## Деплой для Claude

1. Проверить PR, мёржить вручную. Pages выкладывает FLOCK при push в `main`; бот — **отдельный Railway service**, не Pages.
2. Railway: источник этот репозиторий, **root directory `/`**, custom config path `/bot/railway.json`, Dockerfile `bot/Dockerfile`. Build context — корень репо, чтобы `COPY public/flock` работал. Не ставить root directory `bot/`.
3. Привязать постоянный Volume с mount path `/data`; указать три обязательные переменные. Контейнер использует стандартного root-пользователя Node image, чтобы новый root-owned Railway Volume был доступен для записи. SQLite-файл создаётся с правами `0600`.
4. Оставить **одну реплику**, выключить serverless/sleep и не запускать второй poller с тем же токеном. Не включать paid broadcasting. Публичный адрес не нужен для long polling; HTTP `/healthz` нужен только healthcheck и не раскрывает данные.
5. Если бот уже обслуживает другой процесс/ветку Grok, сначала согласовать переключение в рамках деплоя и остановить старый процесс. При существующем webhook сервер завершится с `existing_webhook`, не перехватывая его. После остановки старого сервиса Claude удаляет старый webhook (`deleteWebhook`, без удаления pending updates), затем запускает этот контейнер.
6. Для отправки именно карточки через выбор чата в **BotFather** включить `/setinline` для `@DragonVerseBot` (placeholder: «Показать моего дракона») и `/setinlinefeedback` → **100%**. Эти настройки Bot API изменить не позволяет. Пока inline выключен, бот отправляет карточку с реферальной подписью и инструкцией пересылки; запасная кнопка делится ссылкой. Счётчик подтверждённых отправок в таком режиме недоступен.
7. Для Mini App достаточно HTTPS `web_app`-кнопки; дополнительно можно настроить Main Mini App / Menu Button в BotFather на `GAME_URL`. Имя бота в реферальных ссылках берётся из `getMe`, не из пользовательского ввода.
8. Проверить в Telegram с двух тестовых аккаунтов: `/start`, карточка, Mini App, кормление/блокировка повторного, inline-отправка, переход второго аккаунта по реферальной ссылке, `/stats` владельца и отказ для другого аккаунта. Перезапустить Railway и проверить сохранность дракона/лимита.

Локальная проверка на Node 22:

```sh
cd bot
npm ci
npm test
npm run preview
```

`preview/` содержит яйцо и три JPG-карточки, игнорируется Git. Для запуска задать обязательные переменные окружения и `npm start`. Docker: из корня `docker build -f bot/Dockerfile -t dragonverse-incubator .`; запускать с постоянным writable `/data` и env, без помещения токена в Dockerfile/образ.

Бэкап: остановить сервис и копировать весь `DATA_DIR`, включая SQLite WAL/SHM; восстановить его на новый Volume до запуска. Не копировать только активный `.sqlite` во время работы.

## Что означает статистика

- Новые игроки: всё время и последние 24 часа, по **первому** источнику. Рекламные ссылки: `https://t.me/DragonVerseBot?start=tiktok` и `?start=insta`.
- D1/D3/D7: реальные сообщения, нажатия и inline-действия игрока в окнах `[24–48)`, `[72–96)`, `[168–192)` часов с регистрации. Напоминания не засчитываются как возврат. В знаменателе только игроки, у которых соответствующее окно **полностью завершилось**; незрелая когорта показывается отдельно.
- «Открыли Показать друзьям» — намерение. «Карточек отправлено через inline» — `chosen_inline_result`, дедуплицированный по inline message ID. Для точных данных нужен feedback 100%. Обычные ручные пересылки Telegram боту не сообщает — они не объявляются измеренными.
- Эволюции: отдельно переходы к взрослому и титану, по одному событию на игрока/стадию.

## Проверено и ограничения

- `npm test` в `bot/`: **35/35**, Node **22.23.3**. Детерминизм, вероятности/границы редкостей, SQLite после перезапуска, лимит 24 ч, 3/7, рефералы/самоприглашения, повторные события, напоминания, owner-only stats, inline/fallback, JPEG-карточки и безопасный Mini App адаптер.
- Корневые `npm run typecheck`, **43/43** теста игры, `npm run build` и `npm run verify:bundle` прошли; инкубатор имеет отдельный CI workflow на Node 22.
- Playwright Chromium, 393×852, CPU ×4 и 4G (1.6 Мбит/с, 80 мс): обычный браузер прошёл выбор → имя → логово → бой без JS-ошибок, FCP 412 мс, Telegram SDK вне Telegram не запрашивается. Дополнительно проверены загруженные картинки и реальный ход в бою. Telegram SDK mock на 393×852 и 320×568: имя, ready/expand/fullscreen и haptic работают, все картинки загружены, кнопки боя высотой ≥48 px помещаются, вертикального overflow нет. Скриншоты обоих режимов просмотрены.
- Изображения яйца/карточек реально отрендерены sharp и визуально просмотрены.
- Живой Telegram и Railway не запускались: настоящий `BOT_TOKEN`, ID владельца и существующий сервис не предоставлены. Владельцу не требуется править код — Claude завершает настройки и smoke после мёржа/деплоя.
- Dockerfile подготовлен; сборка Docker требует Docker runtime, которого в рабочем окружении нет. Node 22, зависимости и sharp проверены локально.
- Полноэкранный режим и вибрация проверены программно с Telegram SDK mock; физический iPhone smoke выполняется после деплоя.
